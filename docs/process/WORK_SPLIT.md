# Распределение работы между двумя AI

Два исполнителя работают в **разных папках**, чтобы не было конфликтов при слиянии.
Общий контракт (интерфейс между ними) описан ниже и в `CONTRACT.md`. Меняется только по согласованию обоих.

| | AI 1 — UI | AI 2 — Logic & Content |
|---|---|---|
| Ветка | `ai1-ui` | `ai2-logic` |
| Папки | `index.html`, `src/ui/`, `src/styles/` | `src/engine/`, `config/`, `tests/`, `docs/` |
| Задачи | Интерактивная фигура тела (SVG), формы ввода, графики с анимацией, панель статусов, баннер эскалации, экспорт PDF/CSV, адаптивность, reduced-motion, клавиатура | Пороги в `config/thresholds.json`, движок статусов, тексты рекомендаций, описания органов, unit-тесты, `README.md`, `docs/DATA_SOURCES.md`, сценарий демо и текст для слайдов |
| Не трогает | `src/engine/`, `config/`, `tests/` | `index.html`, `src/ui/`, `src/styles/` |

## Правила работы
1. Каждый AI работает только в своей ветке и только в своих папках.
2. Общие файлы (`CONTRACT.md`, `WORK_SPLIT.md`, `PROMPT.md`) не править без согласования.
3. Коммит — маленький и понятный, с префиксом `ui:` или `logic:`.
4. Слияние в `main` делает человек после того, как обе ветки проходят проверку (`npm test` и открытие приложения в браузере).
5. Если нужен контракт, которого нет в `CONTRACT.md`, не придумывать свой — написать в описании коммита и поднять вопрос.

## Порядок
- Шаг 0 (до старта обоих): создан `CONTRACT.md` и пустой каркас папок в `main`.
- Шаги 1–3 идут параллельно. AI 1 использует заглушки из контракта, пока движок не готов.
- Шаг 4: слияние, проверка вместе, деплой, демо.

## Промпт для AI 1 — UI

> Ты отвечаешь за пользовательский интерфейс приложения «Astronaut Vitals». Работаешь только в ветке `ai1-ui` и только в папках `index.html`, `src/ui/`, `src/styles/`. Не меняй `src/engine/`, `config/`, `tests/`.
>
> Задачи:
> 1. Страница `index.html` — тёмная космическая тема, высокий контраст, читаемые шрифты. Текст только на английском.
> 2. Интерактивная фигура человека (inline SVG): кликабельные органы — голова/мозг, сердце, лёгкие, кости/скелет, ЖКТ, иммунная система, настроение. При клике показывать панель: функция органа, связанные показатели, текущий статус (зелёный/жёлтый/красный + иконка и текст), короткий совет. Данные берутся из `getOrganInfo()` и `evaluateIndicators()` (см. `CONTRACT.md`).
> 3. Форма ввода: систолическое/диастолическое давление (мм рт. ст.), пульс (уд/мин), глюкоза (мг/дл), температура (°C), сон за 24 ч (часы), настроение 1–5 (кнопки с эмодзи), чекбоксы симптомов. Кнопка «Simulate readings» для демо без ввода.
> 4. Графики трендов по каждому показателю (Chart.js через CDN, версия не моложе двух недель) с плавной анимацией.
> 5. Панель статусов NORMAL / WATCH / ALERT. Пульсирующая анимация для ALERT. Статус не только цветом — ещё иконкой и текстом.
> 6. Баннер эскалации: если `escalate === true`, показать «Contact flight surgeon on the ground».
> 7. Панель рекомендаций `getGuidance()` для WATCH и ALERT, с текстом «decision support, not a medical diagnosis».
> 8. Экспорт сессии в CSV и PDF (PDF через браузерную печать или jsPDF).
> 9. Видимый дисклеймер: «Demo prototype. Not a medical device.»
> 10. Адаптивность: телефон (16px отступы, без горизонтальной прокрутки), планшет, десктоп. `prefers-reduced-motion` отключает анимации. Вся навигация с клавиатуры.
> 11. Пока `src/engine/` не готов — используй заглушки из `CONTRACT.md` в `src/ui/stubs.js`.
>
> Готово, когда: страница открывается по `index.html` (или `npm run dev`), клик по органу показывает данные, форма и графики работают, на телефоне нет горизонтальной прокрутки.
> Коммиты с префиксом `ui:`. В конце — список сделанного и что осталось.

## Промпт для AI 2 — Logic & Content

> Ты отвечаешь за логику, данные и тексты приложения «Astronaut Vitals». Работаешь только в ветке `ai2-logic` и только в папках `src/engine/`, `config/`, `tests/`, `docs/`, а также в `README.md`. Не меняй `index.html`, `src/ui/`, `src/styles/`.
>
> Задачи:
> 1. `config/thresholds.json` — пороги для каждого показателя (NORMAL / WATCH / ALERT) с единицами измерения. Значения должны быть обоснованными и с пометкой «demo thresholds, verify with medical sources». Например: пульс покоя, систолическое и диастолическое давление, глюкоза натощак, температура, сон (часы за 24 ч), настроение 1–5.
> 2. `src/engine/evaluate.js` — функции из `CONTRACT.md`: `evaluateIndicators(readings)`, `getGuidance(indicatorId, status)`, `getOrganInfo(organId)`. Логика эскалации: любой ALERT или два и более WATCH одновременно → `escalate: true`.
> 3. Тексты рекомендаций для каждого WATCH/ALERT: гидратация и отдых при высоком пульсе; упражнения против потери костной массы; корректировка графика сна при недосыпе; проверка с психологом экипажа при низком настроении; и т.д. Коротко, по шагам, на английском.
> 4. Описания органов для `getOrganInfo()`: функция органа, связанные показатели, связь с пятью опасностями полёта (радиация, изоляция, удалённость от Земли, гравитация, закрытая среда).
> 5. Тесты в `tests/` (Vitest или простые assert-тесты): нормальные значения, WATCH, ALERT, эскалация, пустые/некорректные входные данные.
> 6. `docs/DATA_SOURCES.md` — список источников NASA и других агентств из `PROMPT.md`, с описанием, что из каждого взято. Это понадобится для раздела NASA Data и Space Agency Partner Data на странице подачи.
> 7. `README.md` — как запустить, таблица показателей и порогов, источники, раздел «AI tools used» с честным указанием, что код и тексты созданы с помощью AI.
> 8. `docs/DEMO_SCRIPT.md` — текст для 7 слайдов или сценарий 30-секундного видео на английском (название, команда, челлендж, проблема, как работает, UX, данные NASA, будущее).
>
> Готово, когда: `npm test` проходит, все функции из контракта работают с примерами из `CONTRACT.md`, документы написаны на английском.
> Коммиты с префиксом `logic:`. В конце — список сделанного и что осталось.

## Общий шаг (человек, после слияния)
- Слить `ai1-ui` и `ai2-logic` в `main`, проверить вместе (`npm test`, открыть в браузере).
- Задеплоить на GitHub Pages / Netlify / Vercel.
- Записать демо и заполнить страницу подачи по `SUBMISSION_CHECKLIST.md`.
